# payments-api — правила для ИИ-ассистента

Сервис приёма платежей: FastAPI, async SQLAlchemy 2.0, PostgreSQL, Alembic.

## Деньги
- Только целые копейки (`int`) в базе и в расчётах. `float` для денег запрещён.
- Наружу — строка с двумя знаками (`"1500.50"`), разбор и вывод только через `app/money.py`.
- Больше двух знаков после точки — ошибка валидации, не округление.

## Инварианты, которые нельзя ломать
- Создание платежа и возврат идемпотентны по заголовку `Idempotency-Key`. Тот же ключ с другими данными — 409.
- Сумма возвратов никогда не больше суммы платежа (проверка в коде + CHECK в базе + блокировка строки `FOR UPDATE`).
- Подпись вебхука — HMAC-SHA256 от сырого тела, сравнение через `hmac.compare_digest`.
- Каждое событие банка применяется один раз (`webhook_events.event_id` — первичный ключ).
- Статус платежа двигается только вперёд, таблица переходов — `app/state.py`. Событие против таблицы — игнорируется, не применяется.

## Изменения схемы
- Только через миграцию Alembic (`alembic revision --autogenerate`), и миграцию читать глазами:
  автогенерация не удаляет enum-типы Postgres в `downgrade`.
- `tests/test_migrations.py` должен проходить: откат и повторный накат.

## Перед тем как сказать «готово»
```
docker compose up -d db
pytest -q
ruff check . && ruff format --check app tests
```
Новое поведение — новый тест сценария в `tests/test_api.py`. Гонки проверять параллельными запросами (`asyncio.gather`), как в существующих тестах.
